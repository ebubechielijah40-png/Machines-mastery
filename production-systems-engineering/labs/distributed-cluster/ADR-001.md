# ADR-001: Consensus Model: Quorum Consensus vs. Asynchronous Primary-Backup

## Context
When replicating state across multiple nodes, systems must balance consistency, write latency, and availability under network partitions (CAP theorem).

## Options Considered
1. **Asynchronous Primary-Backup:** Primary acknowledges write immediately, replicates asynchronously in the background. Low write latency, but data loss on primary crash and split-brain if primary disconnects.
2. **Synchronous All-Node Replication:** Primary waits for $N$ of $N$ nodes to acknowledge before committing. Zero fault tolerance: single node failure blocks all writes.
3. **Majority Quorum Consensus (Selected):** Primary waits for $\lfloor N/2 \rfloor + 1$ nodes to acknowledge.

## Decision
Adopt majority quorum consensus. Writes commit only when confirmed by a majority.

## Consequences & Tradeoffs
- **Pros:** Strong consistency; tolerates $F$ failures in $2F+1$ cluster; strictly prevents split-brain.
- **Cons:** Write latency bounded by the median replica round-trip; minority partition loses write availability.
