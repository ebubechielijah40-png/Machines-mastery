# Adr-001

Problem: repeated account aggregates become expensive as rows grow. Options: keep scans, add an index, cache results, maintain a transactional summary. Decision for this experiment: compare scan, index and bounded cache in stages. Reason: separate reduced lookup work from avoiding repeated work. Tradeoffs: index storage/build/write cost; cache memory and invalidation; summary-update complexity. Consequence: single-writer cache restriction and an explicit stale-data failure test. Evidence must be actual benchmark samples plus correctness tests; the experiment is not a universally optimal architecture.
