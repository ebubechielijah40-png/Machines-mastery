# ADR-001: Inference Strategy: Dynamic Micro-Batching vs. Single-Item Dispatch

## Context
Production model serving must handle variable request arrival rates while maintaining strict latency SLOs (p99 < 5ms).

## Options Considered
1. **Immediate Single-Item Execution:** Process each request as it arrives. Optimal tail latency at low loads, but poor hardware utilization and high per-request overhead under peak traffic.
2. **Fixed Static Batching:** Wait until a full batch of size $B$ accumulates before running inference. Excellent throughput, but introduces unbounded queue latency during low traffic periods.
3. **Dynamic Micro-Batching (Selected):** Dispatch immediately if queue is small; batch up to `max_batch_size` when load surges.

## Decision
Implement dynamic micro-batching with bounded queue limits.

## Consequences & Tradeoffs
- Amortizes vector processing overhead during traffic spikes.
- Bounds queue latency under low-traffic conditions.
- Requires thread-safe request collection and dispatch orchestration.
