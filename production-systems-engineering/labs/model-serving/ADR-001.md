# ADR001: proposed batching, current serial helper

Status: proposal not implemented by this prototype. Earlier text incorrectly
described a selected dynamic dispatcher as completed. Actual `predict_batch`
loops synchronously through `predict`; `max_batch_size` is not enforced.

Immediate per-item execution, fixed-size accumulation and size-or-deadline
dispatch answer different latency/utilization questions. Waiting only for a full
batch can wait indefinitely under sparse arrivals. Size-or-deadline dispatch
needs a bounded queue, synchronized ownership, cancellation policy, clocks and
observable per-request outcomes. None follows from a loop over an input list.

Before adopting that design, implement and test those state transitions, compare
the same scheduled workload and count queue/rejection time in client latency.
The current benchmark supplies no such experiment or p99 service guarantee.
