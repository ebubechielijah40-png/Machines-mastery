# Solutions: stream boundaries

1. Wire is `00 00 00 03 00 ff 00`. Pending lengths are 1,2,3,4,5,6,0 after successive bytes; after byte four `expected=3`. Only byte seven returns `[b'\x00\xff\x00']`. The buffer includes the header while collecting the payload.
2. The full wire length is ten. Clean EOF occurs at positions 0,6,10; positions 1–5 and 7–9 truncate a frame. No messages is a valid empty stream. A zero-length frame cannot be inferred from EOF.
3. Only four bytes need be copied to learn the declared length. The check rejects before any body copy and clears pending storage. For accepted messages the largest transient pending length is `max+4`. The caller's chunk and completed-message list are separate allocations, so this proof does not bound the program's memory or simultaneous connections.
4. For wire `abcdef`, suppose the first call accepts `ab`; the next call starts at `a` again and accepts four bytes. The peer sees `ababcd`, while the faulty total reaches six. Correct code holds an offset and sends only the remaining suffix, treating no progress or a broken connection as a failure. A nonblocking retry follows readiness, not a busy loop.
5. Every run should reconstruct identical messages and close cleanly. Chunk sizes, short-send counts and buffer-accounting values may differ. Streams can split and coalesce application writes, and receive limits themselves impose chunking; neither observation recovers packet boundaries.
6. A yielding decoder can hand the good frame to its consumer before seeing an invalid next prefix. The consumer may already have committed that message when the iterator raises. A caller expecting all-or-nothing batches must add an explicit transaction layer. Both APIs can be correct with different contracts.
7. Acceptance requires independent boundary, size and state checks. Merely matching `encode` against `decode` can hide a shared wrong endianness or length convention. A literal independently derived vector rules out that specific shared mistake; exhaustive cuts of a small wire exercise split-state transitions.
8. Record a request ID, content digest and committed result under the authenticated principal before acknowledging success. A retry with matching ID/content returns the recorded result; different content under the same ID is rejected. Crash consistency, cache retention and competing writers still need a storage protocol. This is a design answer, not an implementation of durable exactly-once execution.
