# Independent qualitative review — baseline portable edition

Reviewed 2026-10-22 by an independent, read-only review agent. Baseline is the preserved ml-v3 content at commit `6e4402b`; implementation agents are developing bounded units concurrently. This report does not grade those later additions. No domain earns EXCELLENT in this baseline review. Ratings describe teaching artifacts, never learner mastery.

## Method and evidence boundaries

Read AGENTS.md, DEPTH_STANDARD.md, LEARNING_SYSTEM.md, the phase start pages, every existing phase SELF_CONTAINED_GUIDE, all twelve coursebooks, the twenty-three book registry records and existing Code intake/map/first-unit materials. Compared language model, memory, ABI, example and reference pages across all fourteen languages. Inspected five arrays problems through prompt, solution, runnable implementation and oracle tests; inspected representative other topics, machine categories, foundational guides, HDL/C/RISC-V exemplars, reverse-engineering oracle and production designs/code/tests. These are representative qualitative inspections, not a mathematical proof of every file's correctness.

No external original book was inspected in this review. Existing historical intake records are preserved, with their scope distinguished from present source availability. Detailed per-book/per-coursebook findings are in [book-coursebook-audit.json](book-coursebook-audit.json). The main development audit owns full test execution logs; test source inspection here is not reported as a passing test run.

## Critical findings

1. **The self-contained label often describes an assignment template rather than instruction.** Nineteen `SELF_CONTAINED_GUIDE.md` files each contain six instances of “Identify the real system problem…” followed by requests to describe mechanisms and construct examples. The mechanism/example is frequently not supplied. In `05-operating-systems/SELF_CONTAINED_GUIDE.md`, scheduling/virtual-memory/filesystem headings do not teach the mechanisms needed to build their assigned models. The same defect appears across core numbered subjects.
2. **All twelve coursebooks share the same instructional-method body.** The text between “How to read” and “Deep material,” including the system-slowness example, is identical. Topic scope and destination paths differ. These are navigation/method wrappers, not original domain coursebooks. They contain no domain-specific derivation, runnable implementation, actual experiment or separated checkable solutions of their own.
3. **Every language repeats its one minimal example across all twenty-eight numbered pages.** C memory, ABI, examples and reference pages all show the same add/print program; Rust repeats the same integer add/print program, SQL the same events aggregation query, and HDL the same register fragment. The single mechanism sentence sometimes changes, but the required semantics and derivations are absent. Nominally valid syntax does not test ownership, ABI, concurrency or lifetime.
4. **Completion prose overstates educational delivery.** `COMPLETION_REPORT.md` calls the coursebooks replacements for mandatory textbook reading and the foundations/language guides deep; inspected bodies do not support that. `PROGRESS.md` says a self-contained prepared edition covers all listed domains. `DOCUMENTATION_COMPLETENESS.md` requires actual examples and experiments, while many named completed artifacts merely instruct the learner to invent them. Historical test totals in `FINAL_VALIDATION.md` must remain historical and must not be carried forward as current execution evidence.
5. **Book source status is inconsistent.** `BOOK_REGISTRY.md` and `books/code-petzold/source/README.md` correctly identify the source as absent. `books/code-petzold/README.md` still says INSPECTED and implies a current local ignored original; `registries/catalog.json` resource R-CODE has the same portability problem. The first derived unit is worth preserving, but cannot count as fresh source verification. The other twenty-two book entries have no book-specific chapter maps or prepared reconstruction units.

## Concrete accuracy and evidence defects

- **Array auxiliary storage claims:** `08-maximum-burst-load/solution.py` and `20-maximum-product-window/solution.py` iterate over `values[1:]`. On a Python list that slice allocates a list of length n−1, so O(1) auxiliary-space claims in their solution prose do not describe these implementations. Use indexed iteration/an iterator, or state the actual allocation. This is a correctness-of-analysis defect, even when functional tests pass.
- **Quickselect expectation assumptions:** problem 17 always chooses the last element. Expected O(n) requires an appropriate distribution assumption or pivot randomization; the text does not supply it. Sorted/equal data can be quadratic. State worst case and assumptions and demonstrate an adversarial partition-count experiment.
- **Replication evidence does not imply convergence:** executed a bounded local probe with two events for the same key, delivered in opposite orders. Actual outputs were `{'k': 2}` and `{'k': 1}`. Existing test uses independent keys and therefore avoids the conflict. This demonstrates arrival-order behavior; it is not an external-network experiment and does not invalidate an explicitly scoped deduplication model.
- **Production language exceeds implemented scope:** cluster state is in-memory and elections are manually initiated in tests; no automatic election timeout loop or real restart persistence was established. Documentation should teach those limits explicitly whenever discussing crash recovery or consensus guarantees.
- **Incident provenance:** model-serving `POSTMORTEMS.md` labels its condition simulated but states observed PSI `> 1.8`, accuracy collapse and downstream false positives without a direct linked execution record for that incident. Treat it as an illustrative scenario unless a matching actual trace is supplied; generic benchmark evidence is not that incident's evidence.
- **Missing cited originals:** many phase, coursebook and language reference pages contain no concrete versioned primary-source locator supporting their technical assertions. A filename saying REFERENCE is not source verification. Preserve historical resource records; inspect the actual specification/paper section before upgrading the claim.
- **Project descriptions are not executable builds:** shell/allocator/HTTP project READMEs have mechanism arrows and a suggested language, with the same generic checkpoints/tests. Their test-plan prose is not runnable tests or starter code. Do not count sixteen project folders as sixteen completed builds.

## Smaller directories and administrative layers

`experiments/` has careful prediction/observation protocols and seven registered experiment folders; this does not establish observed learner results. `unknown-system-challenges/` correctly identifies only the hidden-state oracle as implemented; other families are planned. `reconstruction-drills/` provides a useful assessment method but no independent unseen transfer suite. `repositories/` explicitly records no upstream checkouts or verified implementation behavior. `notes/` correctly records no learner evidence. `research/` contains infrastructure/benchmark history, not a reproduced primary research result. `templates/`, `registries/` and `tools/` have administrative utility and should be assessed for consistency/test coverage, not counted as educational course completion.

Keep these smaller paths in the remediation inventory. Their honest planned status is useful; replacing it with unsupported completion language would make the repository less reliable.

## Integration recommendations

Preserve existing bounded exemplars, twenty arrays implementations and production/reverse-engineering prototypes. Correct completion/source availability claims immediately. Prioritize mathematical and experimental prerequisites before more architecture descriptions. For every new batch, require a worked trace, independently specified tests, an executed evidence record and an adversarial/transfer task. Do not use this review as evidence that uninspected full source claims are correct or that any learner has acquired the capability.
