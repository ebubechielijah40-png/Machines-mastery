# Unknown-system investigations

Choose a related system the learner has not studied, preserve its reference in a reveal directory and expose only a controlled interface. The first runnable challenge is [the hidden-state oracle](../reverse-engineering-systems/exercises/01-hidden-state/prompt.md). It does not claim cryptographic answer secrecy: source remains locally accessible but is outside the initial route.

Future challenge families: executable with hidden state; bounded binary; synthetic protocol; byte format; database isolation/recovery behavior; logic circuit; embedded block diagram; mechanical linkage. These families are planned, not existing runnable challenges. Prepare one at a time with a source/contract, reproducible reset, query budget, competing-model worksheet, separate hints and reveal, oracle checks and a transfer variant.

Rubric (0–2 each, evidence required): boundary/authorization; useful competing hypotheses; discriminating probes; state discovery; instrumentation limitations; raw evidence; falsification/model revision; replica behavior on withheld inputs; uncertainty; transfer. Score what the investigation establishes, not whether an early guess matches the hidden implementation. A high score still needs delayed reconstruction and review before mastery.
