# Decision hints

1–3. Name the trial before naming its probability. Sum coefficients of(1+x)⁵;
the never-reject thresholdn+1 is part of the search.
4–5. Increasingc removes outcomes. Couple two Bernoulli bits with three masses
so the lower-probability bit is never greater than the boundary bit.
6–8. Hold the rule fixed while changing the generatingp. A higher integer
sample size can also raise the critical count.
9–11. Retain every earlier failed operating point. Distinguish a bounded no-hit
from a theorem that no design exists. A null can assign exactly zero mass to
outcomes that an alternative makes possible.
12–14. Define the event across all possible repeated-data paths. The initial
five-head path can recur in several later rejection events.
15–16. Propagate only paths not already counted. An exhaustive oracle classifies
complete paths; it must not copy the count-state transition loop.
17–19. Use the union bound, not a product of overlapping-look probabilities.
The original horizon is part of the design.
20–22. Numerators/denominators grow even when the number of active states is
small. A dataclass record can be structurally valid yet describe a poorly chosen rule.
23–24. The conditional answer assumes a model; observations must support its
sampling assumptions separately. Keep actual outcomes separate from predictions.
