# Depth standard

A topic is not complete because a README exists. A learner-facing unit is considered **deep** only when it does all of the following.

1. **Problem before vocabulary.** State the real problem that created the concept.
2. **Mechanism.** Trace inputs, state, transformations, outputs, invariants, resource costs, and failure modes.
3. **One layer down.** Connect an abstraction to the lower layer that actually implements it.
4. **Examples.** Include a minimal example, a realistic example, an edge case, and a broken example.
5. **Derivation.** For equations/algorithms, explain where they come from and when assumptions fail.
6. **Executable application.** If the idea can be implemented, include code or a lab—not prose alone.
7. **Experiment.** Make a prediction, change one variable, measure, and explain the result.
8. **Production thinking.** Address scale, latency, memory, concurrency, observability, security, and recovery when relevant.
9. **Tests.** Include questions that require explanation, transfer, debugging, and design—not only recall.
10. **Limits.** Explicitly state what the model does not establish.
11. **Provenance.** Separate source claims, derivations, explanations, measurements, and uncertainty.
12. **Reconstruction.** Mature units end with a build/rebuild exercise performed without copying the reference.

A template that merely says “explain the mechanism” does not pass this standard. The explanation itself must be present.

## Classification and review evidence

Use these artifact-quality classifications independently of learner mastery.
Always scope a rating to a unit versus its whole domain.

| Classification | Required interpretation |
| --- | --- |
| EXCELLENT | Substantial, accurate, source-grounded instruction; examples, assessments, implementation/experiments where applicable; documented qualitative review and verified evidence for all applicable gates |
| STRONG | Technically useful developed instruction/implementation, with explicit remaining limitations |
| PARTIAL | Meaningful material exists but essential components remain missing |
| SCAFFOLDED | Mostly outline, repeated template, plan or placeholder |
| BLOCKED | A specific unavailable source/tool/permission prevents the scoped task; independent original work may continue |

Each rating names inspected paths, claim-level source scope, commands actually
executed, raw evidence, review findings and remaining gaps. Neither a word
threshold, minimum paper/file quota nor a passing validator assigns a rating.
An excellent bounded unit cannot promote its entire domain automatically.

Experiments distinguish prediction, procedure, actual run data, analysis,
alternative explanations and limitations. No physical measurement or published
result is reproduced merely because a numerical toy agrees with an equation.
Metadata inspection never becomes a full-text research reconstruction.

Perform separate qualitative review and address its concrete findings. Record
unresolved review items rather than manufacturing a passing status. The quality
auditor inventories risks and checks evidence paths; it cannot establish that
prose is true or evidence supports a claim.
